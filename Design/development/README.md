# LegWeaver の開発体制（再現のための説明）

LegWeaver を、誰が何を担当して作ったかをまとめた物です。同じような体制で開発したい人が再現できるように書いています。
図は `structure.png`（元の文は PlantUML の `structure.puml`）。

LegWeaver は、作者（人）が方針を決め、Anthropic の Claude（Claude Code）が実装・確認・文書の大部分を行って作りました。

## 登場する役

| 記号 | 役 | モデル | 担当 |
|---|---|---|---|
| 作者 | 人 | — | 方針と判断、公開の許可。依頼は短く、結果は画像と表で確かめる |
| O A | メインのセッション | Claude Opus 5.5（Claude Code デスクトップ） | 実装・回帰・文書・コミット、公開候補と Release の作成、サブエージェントへの依頼 |
| O B | 別のセッション | Claude Opus 5.5 | 写真だけを見て、工学的・製品として汚い所を挙げる（実装は知らせない） |
| O C | 別のセッション | Claude Opus 5.5 | リリース用の道具の把握 |
| F | サブエージェント | Claude Fable 5.1 | 見た目の判断。本来の色の写真で、実物と比べて「遠い／おおむね近い／近い」と、気になる所・直す順を返す。設計書の書き起こしと、公開前の最終チェック |

別の会社の AI は使っていません。

## 進め方（1 つの改良の回り方）

1. 作者が依頼する（例:「このアバターだとレッグラップが浮いて見える」）。
2. O A が原因を数値で確かめ（例: リボンと服の面の間の距離）、直す。
3. 回帰: 変えた種類 × 問題の出やすい体で確かめ、まとまった区切りで、手元の全部のアバター × 全種類を流す。
   ほかの種類の出力がバイト単位で変わらないことも見る。
4. 見た目: Unity で本来の色のまま近くから撮り（拡大写真）、F に判定を頼む。形の確認画像（体と布を単色で塗った物）は
   色や質感を誤るので、F の判定には使わない。
5. F の「直す順」を O A が取り込み、2 に戻る。判定・判断・残りは、作者が読める形の記録に残す。

## 独立した確認の決まり

- 監査や読み合わせを頼むサブエージェントは、毎回、作業の経緯を知らない新しい物にする。渡すのは対象と制約だけで、
  親の結論は渡さない（親の考えに引きずられないため）。
- 公開候補の監査は、公開前の決まり（取得の方法、書き込み先の限定、GitHub の状態を変えない、見つけた値は伏せる）に従う。
  監査役が決まりを外れたら止めて報告し、別の新しい監査役でやり直す。
- 公開用のリポジトリは、開発用（非公開）とは別に、利用に要る物だけで作る。開発の履歴は引き継がない。

## 再現に要る物

- Claude Code（デスクトップ）と、Opus・Fable・Sonnet を使えるプラン。
- Unity 2022.3、Blender 5.2、確認用のアバター（市販品）。
- 回帰・撮影・測定の開発用の道具（自作。公開していません）。
