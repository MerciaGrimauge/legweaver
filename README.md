# LegWeaver

VRChat アバターの体に合わせて、タイツ・ソックス・手袋・アームカバーのメッシュを Blender で生成する Unity エディタ拡張です。
本リポジトリはライセンスに従う限り、このリポジトリを技術的等の優位性で潰す目的の敵対的フォーク
単にそのバージョンで固定したいからそっくりそのまま持っていく保守的フォーク

リバースエンジニアリング、改良を極めて強く歓迎します。一方でフォークしたストリームが本家に対する還元は極めて否定的です。
PRは要りません。こっちを潰してください。
勝手に有料アプリケーションとして販売（ただし、これはあくまでもGPLがそれを許可しなければならない。というだけなので、販売先プラットフォームの規制からは逃げられない）
勝手に有料サポートサービスで金を稼ぐことなどもご自由にどうぞ。私はそれらを歓迎しています。

パッケージ ID は `io.github.merciagrimauge.legweaver` です。使い方・必要なもの・仕組みは[パッケージの README](Packages/io.github.merciagrimauge.legweaver/README.md) を参照してください。処理の詳しい説明（[ALGORITHM.md](Design/ALGORITHM.md)）と、同等のツールを作る人・保守する人のための設計書・UML の図は、パッケージとは別に [Design/](Design/README.md) にあります。

## 導入

ALCOM に VPM リポジトリ `https://merciagrimauge.github.io/vpm-repository/index.json` を追加し、プロジェクトに LegWeaver を追加します。依存する VRChat SDK（Avatars）・NDMF・lilToon・Modular Avatar は一緒に入ります。Avatar Optimizer は任意で、入っていれば不透明な衣類の下の肌の削除に使います。

別に Blender 5.x 以降（インストール版、またはポータブル版の場所を指定）が必要です。サポートの終わった版は使えないので、2026 年 11 月の時点では 5.2 以降です（詳しくはパッケージの README）。

Unity 2022.3 向けです。Unity 6 では確認していません。対応 OS は Windows だけです（macOS・Linux では動作を確認していません）。

版番号の決まり（何を互換性として守るか）は、パッケージの README の「バージョン規則」を参照してください。生成される形が変わる変更（不具合の修正を含む）はマイナーの版で出すので、形を変えたくない場合はマイナーの範囲を固定してください。

## Q.A
ライセンスの正確な内容は [LICENSE.md](Packages/io.github.merciagrimauge.legweaver/LICENSE.md)（英語が正文）と各ライセンスの全文に従います。この Q.A は作者の考えで、ライセンスに何かを足したり引いたりする物ではありません。

Q.XXに対応して欲しい

Q.サポートをして欲しい

A.それをする金は貰って無い

Q.BOOTH で入手した。BOOTH でもサポートしない？

A.BOOTH にはプラットフォームとしての決まり（ショップの義務）があるので、それに従って、ダウンロードできない・商品の中身がおかしいといった連絡には最低限の対応をします。
ただ、それはいつでもすぐに対応せよとまで求める決まりではないので、早い返事は期待しないでください。機能追加や個別の技術サポートは、BOOTH でもしません。

Q.コードでBlenderとかの制限を掛けている箇所を解除して良い？

A.良いよ！！！！GPL の部分なので、改変して制限を外すのは自由。というか単にBlender5.x固有のSDF処理に依存し過ぎで、4.x以下は動かんってケースと
あまりにもフルすぎるわけわからんパターンの利用を封鎖したいってだけ

Q.私的利用を目的としてプログラムを勝手に変えて良い？

A.良いよ！！！！というか本アプリケーションはそれを想定しているし、あなたに最低限Opus5.0以上の知能を持った自立型AIエージェントが付いていることを前提にしている
ただ、GPLライセンスからは逃げられないから、配布するときには気をつけてね

Q.コードを間違って取り込んでしまった。該当の部分はGPLで既に配布してしまった。どうしたら良い？

A.This code is licensed under the GPL. Nothing more, nothing less. There is no remedy. You'll have to rewind time and undo past mistakes.

っていうのは半分冗談。一応救済が無いわけではない。第8条でその部分を全て対応すれば良い。でももしコードのうち5000行くらいを取り込んでしまっていたら？本当に期日以内の対応はできそう？
配布してない？なら自明だと思うけど。

Q.派生物を非GPLにしたい

A.GPLコード部分に対する質問と解釈する。GPLはこれを認めない

Q.派生物をAGPLにしたい

A.GPLコード部分に対する質問と解釈する。GPL の部分そのものを AGPL に書き換えることはできない。ただし GPLv3 の第 13 条で、AGPLv3 の作品と結合した物は、全体として AGPL の条件で配布できる（GPL の部分は GPL のまま）。13条の話？なら説明しなくてもあなたは理解してるでしょ。

Q.過失は保護される？

A.GPLコード部分に対する質問と解釈する。GPLはこれを認めない。一応過失規程はあるけど、先述の通りこれは万能ではないし、個別の交渉には応じない。

Q.AIが勝手にやった！

A.GPLコード部分に対する質問と解釈する。GPLはこれを認めない

Q.コードの大部分は AI が書いたんでしょ？なら著作権は無いのでは？

A.コードの大部分が AI で作成されたとしても、都度ユーザー（作者）が設計判断をしているとき、これらが一律に AI が書いたステップ数だけを理由に著作性を却下されるかは興味深い。
会話ログを全て提示した時、日本国家の裁判所がこれを機械的に却下するかは私も興味がある。

Q.Blender の中で動く処理（bpy を使う Python）は、本当に Blender の GPL に従わないといけないの？

A.議論の余地はある。ただ、GPL ライブラリを使用する際に開発者に求められる姿勢は、ライセンスに盲目的に従うことではないと思う。
そのうえで、Blender の言い分は間違っているとは思わない。だからそこは従うし、仮に違っていても、そこにも独自に GPL を適用するだけ。

Q.Blender由来でない箇所が明らかにある。そこはGPLにする必要はない

A.だからなに？

Q.Blender由来でない箇所のGPLはリポジトリ開発者は解除出来るの？

A.そこまで見ているなら目測は正しいし、通常は交渉の余地がある。著作権者である私は、自分が書いた部分を GPL 以外の条件でも出せる（別に許諾できる。Blender の中で動く処理は除く。上の Blender の Q.A を参照）。
ただしそれは私だけの権利で、GPL で受け取った人がその部分を GPL から外せるわけではない。既にGPLとして入手したユーザーの自由は以降も保証される。ただ、聞きたいことは多分違うだろう。交渉の余地はない。

A.設計書は問題になるライセンスは入ってないと思うが…
