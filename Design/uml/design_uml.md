# LegWeaver 設計図集（UML）の説明

## 0. この文書について

- **位置づけ**: 動いている LegWeaver（Unity エディター拡張、Blender 側の処理、実行時の部品、シェーダー）から、責務の分け方・データの流れ・状態の移り変わり・主な手順を逆算し、PlantUML の図として書き起こした物です。コードを写したものではなく、図の要素名にクラス・モジュール・設定項目の名前を使うほかは、働きと取り決めだけを自分の言葉で表しています。
- **元にした物**: エディター拡張（C#）、Blender 側（Python）、実行時の部品、シェーダーの各ソースと、利用者向けの説明（README・ALGORITHM）。開発用の検査コードは対象外で、図にも入れていません。
- **ほかの設計書との関係**: 一つ上のフォルダにある処理の仕様（ALGORITHM.md）・基本設計書・2 冊の詳細設計書と、同じ今の形を表します。
- **画像**: 各図の `.png` は、`.puml` を PlantUML（レイアウトは内蔵の smetana）で書き出した物です。PlantUML の処理系（公式の jar、VS Code の拡張など）で描き直せます。
- **長さの単位**: 特に断らない限り実寸（mm・m）です。Blender 側の計算は体のメッシュの単位で行い、受け渡しの JSON にある「1 単位あたりのメートル」で換算します。

### 1.1 各図の要点

- **全体の構成**: 司令塔（GarmentGenerator）が、体の解析・衣装の検出・受け渡し・Blender の実行・組み立て・見た目・取り付けの各部を順に呼ぶ構成です。Blender とは作業フォルダのファイルだけでやり取りし、通信はしません。Modular Avatar・Avatar Optimizer・lilToon は、パッケージの版の定義で有無を見分け、無い物の機能は省きます。NDMF は、ビルド時の処理（肌の追従）とそのプレビューに使います。
- **生成の流れ**: 「包む」だけは Blender を使わず、対象のメッシュを法線方向へずらして作ります。それ以外は Blender の 7 段（体を読む → 範囲を切る → 包絡面 → 肌から浮かせる → つま先の差し替え → 仕上げ → 厚みと書き出し）を通ります。つま先の差し替えは「まとめ」「足袋型」のときだけです。
- **Unity と Blender のやり取り**: Blender はバックグラウンドで動き、エディターは止まりません。ウィンドウがエディターの更新ごとに出力をログへ移し、終了または打ち切りを判定します。時間切れは「実行中」の判定の中で Blender を止めて印を付け、組み立ての入口で失敗として報告します。作業フォルダは成功・失敗・キャンセル・ウィンドウを閉じた時・開始の途中で止まった時のどれでも消します。
- **主なクラス**: 設定（GarmentSettings）は値のほかに「設定から決まる判定」（不透明か、透けて見えるか、肌の写しを使うか、肌を消すか、姿勢の透けを使うか）を持ち、各部はこれを見て振る舞いを決めます。司令塔は開始時に設定の写しを取り、生成中にウィンドウで値が変わっても影響を受けません。
- **種類と設定**: 種類に固有の項目（ウエストの高さ、裾、上端、手袋の長さと指、帯や巻きの寸法など）と、全種類に共通の項目（色・デニール・質感・透け・柄・肌の扱い・詳細の余裕）に分かれます。親指サック・ガーター・レッグラップは肌との隙間に上限（0.3 mm）を掛け、ガーター・レッグラップは影を受けません。
- **状態**: 準備と組み立ては同期処理（画面が止まる）、Blender の実行だけが非同期です。設定の区画は実行中は無効になります。
- **実行時**: アバターに入る独自の部品は「肌の追従データ」だけで、ロジックを持たないデータの入れ物です。ビルド時に NDMF の変形の段階で体のメッシュの写しに適用し、部品自体は取り除きます。シェーダーは lilToon のカスタムシェーダーとして、深度だけの先行パスと「姿勢に応じた透け」の計算だけを足しています。

## 2. 図だけでは分からない取り決め

### 2.1 Unity と Blender の受け渡しの形（概要）

| ファイル | 向き | 内容の概要 |
|---|---|---|
| `job.json` | Unity → Blender | 体の頂点数・三角形数、1 単位あたりのメートル、入出力ファイルの場所、目印（Humanoid の骨の位置。体のメッシュ空間）、足の指ごとに骨を持つ体では頂点ごとの指の番号、衣装の設定（種類の識別子と、判定を済ませた数値・真偽値） |
| `input.bin` | Unity → Blender | 体の配列を決まった順に並べた物: 位置、法線、UV、脚ウェイト、関節の混ざり、下に着る物の高さ、上に着る物の天井、三角形 |
| `under.bin` | Unity → Blender | 下に着る物の面（体のメッシュ空間）: 頂点数、三角形数、位置、三角形 |
| `output.bin` | Blender → Unity | 衣装の配列を決まった順に並べた物: 位置、法線、体の UV、結び付けた体の三角形と重心座標、三角形、体の頂点ごとの覆いの深さ、伸びのマスク、三角形ごとの部位番号、脚の座標、下着の三角形と重心座標（無ければ負の番号） |
| `output.json` | Blender → Unity | 成否、エラー文（失敗時は例外の内容と追跡）、件数、覆った体の頂点数、品質の報告、リボンの垂れの情報 |

- 数値は 32 ビットの浮動小数と整数で、文字コードや改行に依存しません。パスの区切りは `/` に統一します。
- 衣装の設定の鍵は、全種類で共通の物を常に書き、種類に固有の物（足袋型、ガーター、レッグラップ）はその種類のときだけ書きます。種類を増やしても、ほかの種類の `job.json` が変わらないようにするためです。
- Blender の進み具合は、標準出力の決まった印で始まる行で知らせます。Unity はその行だけを「最新の進み具合」として画面に出し、全体はログとして保持します（保持と表示にはそれぞれ上限があります）。

### 2.2 互換性として守る物

- **部位の番号**: 衣装の部位（脚・パンティ部・帯・補強・フェイクの上部・靴下の帯・縫い目・マチ）は、C# の列挙と Blender 側の定数で同じ順番を保ちます。Blender は三角形ごとにこの番号を書き、Unity はその順でサブメッシュとマテリアルを作ります。
- **メッシュの UV チャンネルの役割**: UV0 に伸びのマスク、UV1 に柄の座標、UV3 に姿勢の透けの係数、UV4 に脚の座標、接線に「曲がりを測るベクトル」。シェーダーと柄のテクスチャはこの割り当てに依存します。
- **シェーダーの名前とプロパティ**: 透ける衣装のマテリアルはカスタムシェーダーの名前で見つけ、姿勢の透けの強さは決まったプロパティ名で渡します。2 層式は同じ面に裏地と外側の 2 つのマテリアルを重ねます。
- **生成物の名前**: 衣装のオブジェクトは「種類のラベル_デニールD」、レンダラーは「…_Mesh」、肌の写しは「…_Skin」。ガーター・レッグラップが「前に作ったタイツ・靴下」を見つけるとき、親指サックの上に写しを付けないとき、体の候補からこのツールの生成物を除くときに、この名前と生成物のフォルダの場所を手がかりにします。
- **肌の追従データの並び**: 頂点の一覧、頂点ごとのウェイトの個数、骨の番号の一覧、ウェイトの一覧を順に並べる形です。ビルド時の処理はこの並びと、頂点・骨の番号が体のメッシュの範囲にあることを確かめ、合わなければ何もせず警告だけ出します（別のアバターのプレハブから部品が来た場合の備え）。
- **Blender 用スクリプトの場所**: エディター用のアセンブリ定義の GUID から、その隣の `Blender` フォルダを探します。名前で探さないのは、別のパッケージの同名のファイルを拾わないためです。
- **設定の保存先**: Blender の場所、同梱 Python の場所、打ち切り時間（品質ごと）は、エディターの設定（EditorPrefs。プロジェクトの外）に決まった鍵で保存します。

### 2.3 安全上の決まり

- **通信しない**: ネットワークを一切使いません。Blender と Python のサポート終了日の表もツールに内蔵し、ツールの更新で表を更新します。
- **書き出す場所**: 生成中の作業ファイル（体の生のメッシュを含む）はプロジェクトの `Temp` の下の、日時と乱数で名付けた専用フォルダだけに書き、終わり方にかかわらず消します。生成物は `Assets` の下の決まった出力フォルダだけに保存します。アバターのアセット（プレハブ）は書き換えず、プレハブが指定されたときはシーンに配置した写しに対して処理します。
- **対象の確認**: 指定したボディ・包むメッシュは、そのアバターのシーン上の子でなければ処理を始めません（別のアバターやアセットを書き換えないため）。Humanoid でないアバター、必要な骨の無い体は始めません。
- **外部プログラムの起動**: 起動するのは Blender だけで、工場出荷の設定・バックグラウンドで、スクリプトの場所と `job.json` の場所を渡します。Blender の場所は、保存された指定か、Windows のインストール済みプログラムの記録、Program Files の下から探し、どれも「Blender の配置である」こと（版のフォルダとスクリプトのフォルダがある）を確かめてから使います。サポートが終わった版・終了が近い版（内蔵の表で判定。終了 90 日前から不可、180 日前から警告）は、場所を自分で指定した場合でも使いません。Blender 側はバイトコードのキャッシュを作りません。
- **受け取る物の検査**: Blender から受け取るファイルは大きさが件数と合うこと、三角形の番号が範囲内であることを確かめ、合わなければ失敗とします。Blender 側でも、計算の細かさ・隙間・厚みがウィンドウの許す範囲を外れていれば拒みます（手で書き換えたジョブでメモリを使い切らないため）。
- **止め方**: 打ち切り時間（10〜600 秒。既定は通常 60 秒・高品質 90 秒）を超えた Blender は強制終了します。キャンセル・ウィンドウを閉じた時も同じです。
- **元に戻せること**: 生成で追加するオブジェクトと部品は Undo の対象です。
- **ログ**: コンソールには、メッシュやシェイプキーの名前、保存先が出ます。文書や報告にはこれらを伏せる配慮が要ります。

## 3. 設計上の主な方針（図の読み方の補足）

- **布は肌の押し出し**: 布のどの頂点も体の一点に結び付き、その点のボーンウェイトとシェイプキーを受け継ぎます。だからどの姿勢でも肌と同じように動き、Unity 側は結び付けの情報だけからメッシュを組み立てられます。
- **判定は設定側で済ませる**: 透けるか・不透明か・写しを使うか・肌を消すかは設定から決まる判定として一か所に置き、Blender に渡す値、マテリアル、肌の削除、追従データがそれを共有します。
- **汎用の処理だけ**: 特定のアバター向けの分岐を持たず、体の問題（肌の欠け、描かれた脚、口ゴムの位置）は警告で知らせるだけです。
- **無い物は省く**: Modular Avatar が無ければ結線と同期をせず、Avatar Optimizer が無ければ肌を消さず、肌の写しを作れなければ肌を消しません（透けて穴が見えるのを防ぐ）。

## 4. 用語

| 用語 | 意味 |
|---|---|
| 司令塔 | 1 回の生成の流れをまとめる物（GarmentGenerator） |
| 脚の座標 | 股関節 0・膝 1・足首 2・つま先 3 とした、脚の骨に沿った位置。腕では肩 0・肘 1・手首 2 |
| 包絡面 | 覆う範囲を閉じて距離場（SDF）にし、隙間＋厚みだけ外へ出した面 |
| 下に着る物／上に着る物 | 布をその上に重ねる物（下着など）／布をその内側に収める物（靴下・靴など） |
| 肌の写し | 透ける布の内側に描く、体の UV とマテリアルを使った肌の面。布と一緒に動く |
| 肌の追従データ | 下着の下に残す肌を下着と一緒に動かすための、頂点ごとの新しいウェイト。ビルド時に適用して取り除く |
| 姿勢に応じた透け | 関節の曲がりを接線の縮みから知り、伸びた所ほど透けさせるシェーダーの働き（PC だけ） |
